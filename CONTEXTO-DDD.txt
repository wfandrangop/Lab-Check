1. Glosario del Lenguaje Ubicuo (Ubiquitous Language)
A partir de tus respuestas, el modelo hablará estrictamente este idioma:

PersonalLaboratorio: El actor administrativo (antiguo encargado/administrador) responsable de auditar los bloques y gestionar el ciclo de vida técnico de los computadores.

BloqueHorario: La entidad que orquesta la apertura de un laboratorio por parte de un profesor para una asignatura específica, delimitando la ventana de tiempo (máximo 2 horas o lo que determine el profesor).

Computador: El activo físico del laboratorio con un identificador de inventario único invariable.

Asistencia: El registro que vincula a un estudiante con un BloqueHorario y un Computador específicos.

ReporteNovedad: El registro de una incidencia técnica en un Computador. Su estado es persistente y es gestionado por el PersonalLaboratorio (PENDIENTE, EN_REPARACION, SOLUCIONADO).

2. Mapa de Agregados y Límites Transaccionales (Bounded Context)
En DDD, definir qué es un Agregado determina cómo se guardarán los datos y qué componentes garantizan las reglas de negocio de forma atómica. Tras tu análisis, el sistema se divide en 3 Agregados principales:

Agregado 1: BloqueHorario (Raíz de Agregado)
Entidades internas: Asistencia (vive y muere con el bloque, si se elimina el bloque, sus asistencias pierden sentido).

Objetos de Valor: RangoTiempo (encapsula hora inicio/fin y valida que no supere las 2 horas), EstadoAsistencia (ACTIVA, CERRADA_MANUAL, EXPIRADA).

Invariantes (Reglas de consistencia que este agregado protege):

El Candado del Tiempo: No se puede registrar una Asistencia si la hora actual está fuera del RangoTiempo o si el estado del bloque es distinto de ACTIVA.

Cierre Flexible: El profesor puede mutar el estado del bloque a CERRADA_MANUAL en cualquier momento (ej. a los 10 minutos), bloqueando inmediatamente futuros registros.

Soporte de Compartición: Permite intencionalmente que múltiples Asistencia referencien al mismo identificador de Computador en la misma sesión (estudiantes trabajando juntos).

Agregado 2: Sala (Raíz de Agregado)
Entidades internas: Computador (tiene identidad propia por su código de inventario único y pertenece permanentemente a una Sala).

Invariantes:

Garantizar que un código de computador no se duplique dentro de la misma sala ni en el sistema global durante el inventario.

Agregado 3: ReporteNovedad (Raíz de Agregado Independiente)
Por qué es independiente: Porque tu regla de negocio dicta que el reporte sobrevivirá al terminar el BloqueHorario. Afecta a los siguientes bloques, por lo que su ciclo de vida lo maneja el PersonalLaboratorio.

Objetos de Valor: EstadoNovedad (PENDIENTE, EN_REPARACION, SOLUCIONADO).

3. Objetos de Valor (Value Objects) Autónomos
Para evitar el "Primitivism Obsession" (usar Strings para todo), el dominio contará con:

CorreoInstitucional: Valida sintaxis y la terminación obligatoria en @uce.edu.ec.

Cedula: Valida el algoritmo de 10 dígitos ecuatoriano de forma aislada.

Para implementar **Domain-Driven Design (DDD)** con éxito en Java 17, la regla de oro es la **pureza del dominio**. Todo el código que verás a continuación es Java puro (POJOs y Records); no encontrarás ninguna anotación de Spring (`@Service`, `@Autowired`) ni de JPA (`@Entity`, `@Table`). La infraestructura se adaptará al dominio después, nunca al revés.

Para mantener los límites transaccionales limpios y evitar un acoplamiento severo en memoria, aplicaremos una regla táctica esencial de DDD: **los agregados se comunican entre sí haciendo referencia únicamente a sus IDs**, no embebiendo objetos completos.

public record Cedula(String value) {
    public Cedula {
        if (value == null || value.length() != 10 || !value.matches("\\d+")) {
            throw new IllegalArgumentException("La cédula debe contener exactamente 10 dígitos numéricos.");
        }
        // Aquí se podría añadir el algoritmo del dígito verificador (módulo 10)
    }

// 3. Rango de Tiempo del Bloque (Máximo 2 horas e inyectable en las ventanas operativas)
public record RangoTiempo(LocalDateTime horaInicio, LocalDateTime horaFin) {
    public RangoTiempo {
        if (horaInicio == null || horaFin == null) {
            throw new IllegalArgumentException("Las fechas de inicio y fin no pueden ser nulas.");
        }
        if (horaInicio.isAfter(horaFin)) {
            throw new IllegalArgumentException("La hora de inicio no puede ser posterior a la hora de fin.");
        }
        if (horaInicio.plusHours(2).isBefore(horaFin)) {
            throw new IllegalArgumentException("Un bloque horario no puede exceder las 2 horas de duración.");
        }
    }
    
    public boolean incluye(LocalDateTime momento) {
        return !momento.isBefore(horaInicio) && !momento.isAfter(horaFin);
    }
}

## 2. Entidades y Raíces de Agregados (Aggregate Roots)

Las raíces de agregados gestionan sus entidades internas asegurando que ninguna regla de negocio sea vulnerada. Tienen identidad única (`Id`) invariable.

### Agregado Sala (Inventario Físico)

La `Sala` es la raíz. El `Computador` es una entidad interna que posee identidad de inventario única (`codigoUnico`), pero no puede ser manipulado fuera del contexto de su sala.

```java
package com.uce.sgalab.domain.model.sala;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Computador {
    private final String codigoUnico; [cite_start]// Identificador de inventario único [cite: 17]

    public Computador(String codigoUnico) {
        if (codigoUnico == null || codigoUnico.isBlank()) {
            throw new IllegalArgumentException("El código de inventario de la PC no puede estar vacío.");
        }
        this.codigoUnico = codigoUnico;
    }

    public String getCodigoUnico() { return codigoUnico; }
}

// Raíz de Agregado
public class Sala {
    private final Long id;
    private final String nombreCodigo; [cite_start]// Ej: "LAB-01" [cite: 15]
    private final List<Computador> computadores;

    public Sala(Long id, String nombreCodigo) {
        this.id = id;
        this.nombreCodigo = nombreCodigo;
        this.computadores = new ArrayList<>();
    }

    // Invariante: No se pueden duplicar códigos de PC en la misma sala
    public void registrarComputador(String codigoUnico) {
        boolean existe = computadores.stream()
            .anyMatch(c -> c.getCodigoUnico().equalsIgnoreCase(codigoUnico));
        if (existe) {
            throw new IllegalStateException("El computador con código " + codigoUnico + " ya está registrado en esta sala.");
        }
        this.computadores.add(new Computador(codigoUnico));
    }

    public Long getId() { return id; }
    public String getNombreCodigo() { return nombreCodigo; }
    public List<Computador> getComputadores() { return Collections.unmodifiableList(computadores); }
}

```

### Agregado BloqueHorario (Control de Asistencias)

`BloqueHorario` es la raíz. La entidad `Asistencia` es interna. El agregado asume la responsabilidad total de evaluar el tiempo y autorizar la compartición de equipos.

```java
package com.uce.sgalab.domain.model.bloque;

import com.uce.sgalab.domain.model.vo.*;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class Asistencia {
    private final Long id;
    private final Long estudianteId;  // Referencia por ID al agregado Usuario
    private final String pcCodigo;    // Identificador de auditoría de la PC
    private final LocalDateTime fechaRegistro;

    public Asistencia(Long id, Long estudianteId, String pcCodigo, LocalDateTime fechaRegistro) {
        this.id = id;
        this.estudianteId = estudianteId;
        this.pcCodigo = pcCodigo;
        this.fechaRegistro = fechaRegistro;
    }

    public Long getEstudianteId() { return estudianteId; }
    public String getPcCodigo() { return pcCodigo; }
    public LocalDateTime getFechaRegistro() { return fechaRegistro; }
}

// Raíz de Agregado
public class BloqueHorario {
    private final Long id;
    private final Long salaId;      // Referencia por ID a Sala
    private final Long profesorId;  // Referencia por ID a Usuario (Profesor)
    [cite_start]private final Long asignaturaId;// Referencia por ID a Asignatura [cite: 22]
    
    private RangoTiempo rangoTiempo;
    private EstadoBloque estado;
    private final List<Asistencia> asistencias;

    public BloqueHorario(Long id, Long salaId, Long profesorId, Long asignaturaId, RangoTiempo rangoTiempo) {
        this.id = id;
        this.salaId = salaId;
        this.profesorId = profesorId;
        this.asignaturaId = asignaturaId;
        this.rangoTiempo = rangoTiempo;
        this.estado = EstadoBloque.ACTIVO; // Inicia habilitado por el profesor
        this.asistencias = new ArrayList<>();
    }

    // INVARIANTE: Candado de Validación de Asistencia
    public void registrarAsistencia(Long asistenciaId, Long estudianteId, String pcCodigo, LocalDateTime momentoRegistro) {
        // 1. Validar el estado del candado operativo
        if (this.estado == EstadoBloque.CERRADO_MANUAL) {
            throw new IllegalStateException("El profesor ha cerrado manualmente el registro para este bloque.");
        }
        
        // 2. Validar expiración automática por tiempo
        if (!this.rangoTiempo.incluye(momentoRegistro)) {
            this.estado = EstadoBloque.EXPIRADO;
            throw new IllegalStateException("El tiempo establecido para este bloque horario ha expirado.");
        }

        // Regla de Negocio: Está permitido compartir PCs (asistencias con mismo pcCodigo son válidas)
        Asistencia nuevaAsistencia = new Asistencia(asistenciaId, estudianteId, pcCodigo, momentoRegistro);
        this.asistencias.add(nuevaAsistencia);
    }

    // Acción del Profesor: Cierre metodológico anticipado
    public void cerrarManualmente() {
        this.estado = EstadoBloque.CERRADO_MANUAL;
    }

    public Long getId() { return id; }
    public Long getSalaId() { return salaId; }
    public EstadoBloque getEstado() { return estado; }
    public List<Asistencia> getAsistencias() { return Collections.unmodifiableList(asistencias); }
}

```

## 4. Servicio de Dominio (Domain Service)

¿Qué pasa si una regla de negocio requiere interactuar con dos agregados distintos que no pueden contenerse el uno al otro? Usamos un **Domain Service**.

*Regla:* El estudiante no puede registrar asistencia en un `BloqueHorario` indicando una PC que no existe físicamente en la `Sala` asociada a ese bloque.

```java
package com.uce.sgalab.domain.service;

import com.uce.sgalab.domain.model.bloque.BloqueHorario;
import com.uce.sgalab.domain.model.sala.Sala;
import com.uce.sgalab.domain.repository.SalaRepository;
import java.time.LocalDateTime;

public class VerificacionAsistenciaDomainService {
    private final SalaRepository salaRepository;

    public VerificacionAsistenciaDomainService(SalaRepository salaRepository) {
        this.salaRepository = salaRepository;
    }

    public void verificarYRegistrar(BloqueHorario bloque, Long asistenciaId, Long estudianteId, String pcCodigo) {
        // 1. Cruzar datos con el Agregado Sala para validar la infraestructura física
        Sala sala = salaRepository.findById(bloque.getSalaId())
            .orElseThrow(() -> new IllegalArgumentException("La sala asociada al bloque no existe."));
            
        boolean pcExisteEnSala = sala.getComputadores().stream()
            .anyMatch(pc -> pc.getCodigoUnico().equalsIgnoreCase(pcCodigo));
            
        if (!pcExisteEnSala) {
            throw new IllegalArgumentException("Operación Inválida: La computadora " + pcCodigo + " no pertenece físicamente a la sala " + sala.getNombreCodigo());
        }

        // 2. Si la infraestructura es correcta, delegar al Agregado correspondiente la ejecución de sus propias invariantes
        bloque.registrarAsistencia(asistenciaId, estudianteId, pcCodigo, LocalDateTime.now());
    }
}

```

2. ¿Cómo los genera el Agregado? (Modificación en BloqueHorario)
Para que el diseño sea DDD puro, la Raíz de Agregado debe generar el evento en su memoria interna cuando se ejecuta una acción de negocio. Solo tienes que agregar una lista y mutarla en los métodos que ya creamos:

Java
package com.uce.sgalab.domain.model.bloque;

import com.uce.sgalab.domain.model.event.*;
import java.time.LocalDateTime;
import java.util.ArrayList;
import java.util.List;

public class BloqueHorario {
    private final Long id;
    private final Long salaId;
    private EstadoBloque estado;
    private final List<Asistencia> asistencias = new ArrayList<>();
    
    // El secreto de DDD: El agregado acumula sus eventos de forma local
    private final List<EventoDominio> eventosRegistrados = new ArrayList<>();

    public BloqueHorario(Long id, Long salaId, Long profesorId, Long asignaturaId, RangoTiempo rangoTiempo) {
        this.id = id;
        this.salaId = salaId;
        this.estado = EstadoBloque.ACTIVO;
        
        // Se dispara el evento de apertura
        this.eventosRegistrados.add(new BloqueHorarioActivado(id, salaId, LocalDateTime.now()));
    }

    public void registrarAsistencia(Long asistenciaId, Long estudianteId, String pcCodigo, LocalDateTime momento) {
        if (this.estado != EstadoBloque.ACTIVO) {
            throw new IllegalStateException("Bloque no activo.");
        }
        
        this.asistencias.add(new Asistencia(asistenciaId, estudianteId, pcCodigo, momento));
        
        // Se dispara el evento de asistencia
        this.eventosRegistrados.add(new AsistenciaRegistrada(this.id, estudianteId, pcCodigo, momento));
    }

    public void cerrarManualmente() {
        this.estado = EstadoBloque.CERRADO_MANUAL;
        
        // Se dispara el evento de cierre
        this.eventosRegistrados.add(new BloqueHorarioCerrado(this.id, "Cierre manual por el Profesor", LocalDateTime.now()));
    }

    // El servicio de aplicación usará este método para leer los eventos y limpiarlos
    public List<EventoDominio> extraerEventos() {
        List<EventoDominio> copia = new ArrayList<>(this.eventosRegistrados);
        this.eventosRegistrados.clear();
        return copia;
    }
}
3. El Publicador de Eventos (La Infraestructura Express)
Para cumplir con el examen sin complicarte la vida, implementa un publicador estático súper simple que use programación reactiva funcional nativa de Java (Consumer).

Java
package com.uce.sgalab.infrastructure.event;

import com.uce.sgalab.domain.model.event.EventoDominio;
import java.util.ArrayList;
import java.util.List;
import java.util.function.Consumer;

public class PublicadorEventosExpress {
    private static final List<Consumer<EventoDominio>> suscriptores = new ArrayList<>();

    // Permite suscribir "escuchadores" (Ej: enviar correos, auditoría, logs)
    public static void suscribir(Consumer<EventoDominio> suscriptor) {
        suscriptores.add(suscriptor);
    }

    // Publica los eventos acumulados
    public static void publicar(List<EventoDominio> eventos) {
        eventos.forEach(evento -> suscriptores.forEach(s -> s.accept(evento)));
    }
}
